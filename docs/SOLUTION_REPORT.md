# Отчёт о ходе решения

3D Mesh Quality Control, AI Journey 2026.
Документ фиксирует путь от базового решения до текущего результата: гипотезы,
измерения, отрицательные результаты и методологические выводы. Материал рассчитан
на то, чтобы блоки презентации собирались отсюда напрямую.

---

## 1. Постановка и чем она необычна

Одиннадцать бинарных меток на объект: десять дефектов и `quality` — «дефектов нет».
Метрика `10 · F1(quality) + 10 · F1_weighted(10 дефектов)`.

Три особенности задачи определили всю дальнейшую работу.

**Половина метрики зависит от одной метки.** `quality` даёт 10 баллов из 20,
и по определению `quality = 1` ⟺ ни один из десяти дефектов не поставлен. Одна
ложная сработка среди дефектов обнуляет вклад объекта в обе половины сразу.

**Веса классов известны заранее.** `average='weighted'` считает по support истинных
меток, а не предсказанных. Значит потолок вклада каждого класса вычисляется до
обучения, и понятно, куда вообще имеет смысл вкладываться.

| класс | вес | потолок, баллов |
|---|---|---|
| noisy | 0.274 | 2.75 |
| simple | 0.208 | 2.08 |
| abstract | 0.129 | 1.29 |
| lowpoly | 0.119 | 1.19 |
| set | 0.100 | 1.00 |
| open | 0.059 | 0.59 |
| artifacts | 0.047 | 0.47 |
| partial | 0.041 | 0.41 |
| intersection | 0.012 | 0.12 |
| scale | 0.012 | 0.12 |

`intersection` и `scale` вместе стоят 0.24 балла даже при идеальном предсказании.
Работа над ними экономически бессмысленна, и это выяснилось до того, как на них
было потрачено время.

**Тест мал.** 669 объектов. Бутстрап на подвыборках такого размера даёт для одной
и той же модели **14.404 ± 0.384**, 95% интервал [13.61, 15.15]. Разница двух
сабмитов меньше 0.8 балла статистически неразличима. Этот факт определил всю
методологию: лидерборд использовался только для финальной проверки гипотез,
а решения принимались по внутренней оценке.

## 2. Данные

8964 объекта train, 669 test. На объект приходится:

* `.npz` с вершинами и гранями меша;
* PNG-лист 1536×1024 с шестью ракурсами в раскладке 2×3 — четыре азимута с шагом
  90°, вид сверху и вид снизу. Нативный размер одного ракурса — **512 px**.

### Находка: неиспользованное разрешение

Базовое решение подавало в сеть 224×224 на ракурс, то есть использовало меньше
пятой части доступных пикселей. Обнаружение этого стало одним из двух решающих
улучшений: переход на 336 поднял одиночную модель с 14.25 до 14.39, а источник
на 448 оказался сильнейшим в ансамбле (14.685).

### Находка: группа симметрий съёмочного стенда

Четыре азимута с шагом 90° плюс два полюса образуют конфигурацию с **16 точными
симметриями**: поворот вокруг вертикали (4) × зеркало (2) × переворот верх-низ (2).
Каждая переставляет и отражает кадры, но множество из шести картинок остаётся тем
же — значит **все 11 меток инвариантны по построению**.

Это дало 16-кратную аугментацию с нулевым риском испортить разметку, в отличие от
приёмов, которые казались естественными, но метки ломают:

| преобразование | что ломает |
|---|---|
| зум, RandomResizedCrop | `scale` — метка буквально про размер объекта в кадре |
| пиксельный шум | `noisy` — класс с наибольшим весом 0.274 |
| обнуление вида | `partial` — «не видно с некоторых ракурсов»: мы сами создаём это условие |
| `np.roll` | заворачивает объект с противоположного края — физически невозможный кадр |

Отдельно: базовый флип отражал все шесть кадров, но **не разворачивал порядок
азимутов**. Зеркало отображает азимут k в −k, и без разворота получалась
конфигурация, которой не соответствует ни один реальный объект.

### Находка: топология не объясняет топологические классы

Посчитаны сварка дублированных вершин, граничные рёбра, non-manifold, watertight,
двугранные углы, качество треугольников, самопересечения через `cKDTree`, связные
компоненты, выпуклая оболочка — 235 признаков.

Лучший признак на каждый класс:

| класс | признак | r |
|---|---|---|
| noisy | `clip_p_noisy_mean` | +0.611 |
| abstract | `ncc_range` | +0.515 |
| simple | `clip_p_noisy_mean` | −0.423 |
| set | `clip_p_multi_mean` | +0.361 |
| lowpoly | `uniq_normals_q1` | +0.354 |
| open | `pxstd_std` | +0.187 |
| artifacts | `clip_p_noisy_mean` | +0.163 |
| intersection | `ext_min` | +0.076 |

`open` определён через незамкнутость, `intersection` — через самопересечения,
и оба признака посчитаны. Но объясняют эти классы не они, а силуэтная статистика
кадра и CLIP, причём слабо. Наиболее правдоподобное объяснение — противоречивая
разметка: F1 этих классов 0.33 и 0.15 не поднялся ни одним из испробованных
подходов.

CLIP zero-shot оказался сильнейшим отдельным источником признаков — топ-предиктор
для четырёх классов из одиннадцати.

## 3. Архитектура решения

**Вход:** 6 ракурсов → общий бэкбон → ML-Decoder → 11 логитов. Параллельно
гео-ветка: MLP над табличными признаками, вливается в голову.

**ML-Decoder** (Ridnik et al., WACV 2023). Обучаемый запрос на каждый класс,
cross-attention к патч-токенам всех видов, без self-attention между запросами.
Мотивация: глобальный пулинг сжимает кадр в один вектор, и сигнал локального
дефекта — дыры, занимающей малую долю кадра — разбавляется в сотни раз.
Патч-сетка каждого вида ужимается до 8×8, поэтому в декодер приходит 385 токенов
независимо от разрешения: переход на 448 удорожает бэкбон, но не голову.

**Функция потерь:** `0.35 · BCE(pos_weight) + 0.65 · AsymmetricLoss`.

**Обучение:** AdamW, послойное затухание LR, cosine с разогревом, AMP, накопление
градиента до эффективного батча ~24, EMA весов, snapshot-ансамбль из трёх лучших
эпох, TTA по 8 симметриям.

**Валидация:** `MultilabelStratifiedKFold(5, shuffle=True, random_state=42)`.
Порог каждого класса — точный argmax F1 за один проход сортировки: отсортировав
по убыванию вероятности, `F1@k = 2·TP@k/(k+P)`, достаточно взять максимум по k.
Перебор сетки 0.02 это лишь приближал и стоил в 50 раз дороже.

## 4. Ключевой методологический инструмент: вложенная оценка

Решающее правило (веса бленда, пороги, стратегия `quality`) само настраивается по
данным. Если настраивать и проверять его на одном и том же OOF, получается
завышенная оценка.

Вложенная кросс-валидация: правило настраивается на четырёх фолдах, метрика
считается на пятом. Разрыв между обычной OOF-оценкой и вложенной **и есть**
величина переобучения правила.

На базовом решении этот разрыв составлял **0.35 балла**: OOF 14.474 против
вложенной 14.124. То есть весь прирост от второго уровня (GBM, стэкинг, powerset,
по-классовые веса) оказался фикцией. После перехода на глобальные веса разрыв
сократился до 0.12.

## 6. Что дало прирост

### Ансамбль разнородных моделей с подобранными весами

Главный источник прироста: +0.30 к уровню лучшей одиночной модели.

Правило отбора — **некоррелированность ошибок при сопоставимой силе**, а не
мощность каждого участника. Корреляции внутри рабочей тройки 0.77–0.84.

Два наблюдения, подтверждающие правило с разных сторон:

* Источник, слабее лучшего на 1.7 балла (12.08 против 13.79), в ансамбле получил
  вес 0.25 и дал прирост 0.008 — то есть ничего. Никакая корреляция не спасает
  слабого участника.
* Замена участника на более сильный одиночно (ConvNeXt-B: 14.47 против 14.38),
  но с более близкими ошибками, **ухудшила** результат на лидерборде на 0.28.

Равное усреднение опасно: однажды оно смешало модель на 13.8 с моделью на 12.1
поровну и дало 13.67 — ниже лучшей одиночной. Веса подбираются перебором по OOF,
слабый источник отбрасывается автоматически.

### Разрешение

| tile | токенов на вид | одиночная метрика |
|---|---|---|
| 224 | 256 | 14.25 |
| 336 | 576 | 14.39 |
| 448 | 1024 | 14.69 |

### Согласование меток с тождеством разметки

`quality = 1` ⟺ нет дефектов, но правило предсказывает их независимо, поэтому
часть объектов получает противоречивый ответ. В базовом сабмите таких было 36
из 669.

Проверены все шесть вариантов согласования, работает **ровно один**:

| вариант | лидерборд |
|---|---|
| **дописать дефект «плохому без дефектов»** | **15.0016** |
| дописать два дефекта вместо одного | 14.995 |
| он же + обнулить дефекты у «хороших» | 14.988 |
| без согласования | 14.987 |
| выбор дефекта взвешен по цене класса | 14.941 |
| вывести `quality` целиком из дефектов | 14.330 |

Последняя строка содержательна: `quality` предсказывается головой сети лучше, чем
выводится из порогов по дефектам. Это подтвердилось и независимо — см. §7.

### Устойчивый выбор гиперпараметров правила

Проверка по пяти независимым разбиениям вместо одного:

| вариант | среднее | std |
|---|---|---|
| только глобальные веса | 14.299 | 0.011 |
| по-классовые веса (min_support=300) | 14.276 | 0.020 |
| грубая сетка весов | 14.271 | 0.034 |

На одном разбиении победителем оказывался другой вариант. По-классовый подбор
на `intersection` и `scale` со 107 позитивами — подгонка под единичные объекты.

## 7. Отрицательные результаты

Раздел важен не меньше предыдущего: каждая строка — измеренная гипотеза.

| гипотеза | результат |
|---|---|
| DINOv3 сильнее DINOv2 (претрейн 1.689B против 142M) | 13.79 против 14.24 — **хуже** |
| EVA-02-B/14 как источник разнообразия | 2 фолда из 5 схлопнулись при `head_lr_mult=10` |
| второй уровень: GBM + стэкинг + powerset + frozen DINO | 14.317 против 14.329 у чистой CNN — **ноль** |
| пороги по целевой доле вместо абсолютных | 14.734 против 14.987 |
| отдельная модель под `quality` | см. таблицу ниже |
| soft-F1 в функции потерь + голова счёта дефектов | версия с ними дала 13.79 против 14.24 |
| спектр Лапласа-Бельтрами как признак | 27 часов расчёта, вклад ~0 |
| псевдо-разметка теста | 669 объектов, эффект тонет в шуме |

### Почему `quality` не улучшается отдельно

Вложенная оценка восьми методов предсказания `quality`:

| метод | F1 |
|---|---|
| логит-среднее голов всех источников | 0.7233 |
| голова одной сети | 0.7165 |
| логрегрессия на всех вероятностях | 0.7104 |
| LightGBM под `quality` | 0.7088 |
| powerset P(все нули) | 0.7031 |
| Π(1−p) с изотонной калибровкой | 0.7012 |
| мягкое правило Π(1−p) | 0.6910 |
| LightGBM + геометрия | 0.6842 |

Все «умные» методы проиграли простой голове. Разбор ошибок объяснил почему:
среди объектов, ошибочно названных хорошими, у 35% реально есть `lowpoly`,
у 31% `simple`, у 28% `noisy`. **Ошибки `quality` производны от детекции
дефектов** и отдельно не чинятся — его 2.8 балла резерва берутся только через
улучшение десяти дефектов.

### Гипотеза о сдвиге train против test

Внутренняя оценка росла (14.12 → 14.29 → 14.32 → 14.69), лидерборд снижался
(14.99 → 14.90 → 14.76 → 14.64). Проверены три объяснения:

* **Различимы ли выборки.** Классификатор «train против test» по 235 признакам
  дал AUC **0.502**. Выборки статистически неразличимы.
* **Работает ли модель хуже на «тестоподобных» объектах.** На верхних 25% по
  вероятности принадлежать тесту: 14.461 против 14.367 на остальных. Разница
  +0.094, то есть ноль.
* **Помогает ли коррекция долей предсказанных меток.** Ухудшила на 0.25.

Все три отвергнуты. Остаётся объяснение через шум выборки: ранний сабмит попал
в верхнюю часть своего 95%-го интервала.

## 8. Технические находки

Восемь ошибок, каждая стоила времени и могла стоить результата.

**Схлопывание фолда.** Метрика ровно 0.000 по всем классам при падающем loss.
Причина: `head_lr_mult=10` при физическом батче 2 даёт голове LR 3e-3, и на
5–7 эпохе обучение срывается в тривиальное решение «всё ноль» — локальный минимум
с приемлемым BCE при редких классах. Лечится снижением до 3.0. Два фолда из пяти
были потеряны до того, как причина нашлась.

**NaN от переполнения fp16.** Усреднение восьми TTA-проходов в half переполняется,
`p > threshold` с NaN молча даёт False, подбор порога ломается и все F1 выходят
нулевыми — при живой и нормально обученной модели. Лечится приведением к float32
до сигмоиды.

**Потеря данных на Google Drive.** Запись 0.5 ГБ чекпоинта каждую эпоху через
FUSE-монтирование не долетает: файлы пропадают молча либо плодятся конфликтные
копии `fold0 (1).pt`. За один прогон накопилось 6 ГБ дубликатов. Решение: работать
на локальном диске, Drive использовать как зеркало, чекпоинты отправлять раз в три
эпохи и без состояния оптимизатора (оно вдвое тяжелее самих весов).

**Определение типа бэкбона по имени.** В timm имя устроено как
`архитектура.тег_весов`, и `convnext_small.dinov3_lvd1689m` — свёрточная сеть,
дистиллированная из DINOv3. Проверка подстроки по всему имени приняла её за ViT
и передала `img_size`, которого у ConvNeXt нет. Смотреть надо только на часть
до точки.

**Раскладка выходных тензоров.** Swin отдаёт `(N, H, W, C)`, ConvNeXt `(N, C, H, W)`,
ViT `(N, L, C)`. Определять надо по форме, а не по имени модели.

**BatchNorm при батче 1.** Гео-ветка падает с `Expected more than 1 value per
channel`. При tile=448 физический батч равен 1–2, поэтому либо батч ≥ 2,
либо GroupNorm.

**Пустое пересечение масок.** Недоученный прогон с малым покрытием сжимает
пересечение всех источников до нуля и роняет сборку. Нужен порог `MIN_COVER`.

**Выбор порога при совпадающих вероятностях.** Разрез допустим только там, где
значение меняется: иначе порог попадает между двумя одинаковыми `p`, и `p > th`
выбрасывает оба объекта вместо одного. При насыщенных сигмоидах и усреднении
по фолдам совпадения массовые.

## 9. Методологические выводы

**Мелкий тест не даёт обратной связи.** При 669 объектах и разбросе ±0.385
разница меньше 0.8 балла не измеряется. Пять отправок вариаций одной модели
дали 14.518, 14.530, 14.643, 14.741, 14.755 — весь этот разброс шум.
Единственный способ принимать решения — вложенная оценка на 8964 объектах.

**Сравнивать можно только при одинаковом покрытии.** Состав с вложенной 14.916
на 5384 объектах проиграл на лидерборде составу с вложенной 14.855 на 7156.
Меньшая выборка систематически завышает оценку, и разница в 1800 объектов
искажает сравнение сильнее, чем реальная разница между составами.

**Максимум из нескольких близких вариантов — это шум.** Выбор победителя среди
шести вариантов правила на одном разбиении завышал оценку примерно на 0.05–0.10.
Проверка по пяти разбиениям переворачивала порядок.

**Менять по одному.** Версия с восемью одновременными изменениями оказалась
на полбалла хуже базовой, и разобрать, какое именно навредило, стало невозможно.
Последующие изменения вносились поштучно с измерением каждого.

## 10. Текущее состояние и нереализованное

Лучший результат **15.541** при вложенной оценке 14.855. Состав: три CNN
на разрешениях 336 / 448 / 224, веса 0.75 / 1.00 / 0.50.

Конфигурация источника `dino448_s2` восстановлена по исходному рабочему
ноутбуку: `vit_small_patch14_reg4_dinov2.lvd142m`, tile 448, 16 эпох,
backbone LR `4e-5`, layer decay `0.75`.

Оставшийся резерв, по разложению метрики: 2.80 балла в `quality` (производен от
дефектов) и 1.76 в четвёрке `simple`, `noisy`, `lowpoly`, `open`.

Что не успели проверить:

* **Прямая работа с геометрией** — PointNet или графовая сеть по мешу. Единственный
  принципиально другой канал информации: `intersection` и `open` — свойства,
  невидимые снаружи при любом разрешении, а вся модель смотрит только на рендеры.
* **Разрешение 504** — полный нативный размер ракурса. Ожидаемый прирост
  небольшой: отдача от разрешения выходит на плато между 336 и 448.
* **Работа с шумной разметкой** — повышенное label smoothing для объектов
  с наибольшим расхождением предсказания и метки. Целится в диагноз, а не в
  симптом, но рискует выбросить настоящий сигнал.
